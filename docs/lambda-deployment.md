# Deploying to AWS Lambda with SAM

This repository uses AWS SAM to deploy the FastAPI API Lambda and an SQS worker
Lambda, both as Python 3.12 ZIP packages. API Gateway accepts analysis requests
quickly; SQS invokes the worker for the longer MAI call. SAM builds the package,
uploads it to S3, and creates the functions, queue, API, and execution roles
from [`template.yaml`](../template.yaml).

## First deployment

### 1. Install the tools and connect your AWS account

Install the [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)
and [AWS SAM CLI](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/install-sam-cli.html).
Install Docker too if you plan to use `sam build --use-container`.

Sign in with an AWS profile that can create CloudFormation stacks, Lambda,
SQS queues, API Gateway, IAM roles, and an S3 deployment bucket. If your organization uses
AWS IAM Identity Center, run `aws configure sso`; otherwise configure a profile
using your normal AWS account process. Confirm the selected account with:

```bash
aws sts get-caller-identity
sam --version
```

Do not paste AWS credentials or secret keys into chat.

The previous attempt authenticated successfully but AWS denied
`cloudformation:CreateChangeSet` on `aws-sam-cli-managed-default`. Ask the AWS
administrator to grant the SAM deployment permissions to your IAM principal
before retrying. `aws sts get-caller-identity` confirms who is signed in; it
does not confirm CloudFormation deployment permission.

### 2. Build the Lambda package

From the repository root:

```bash
sam validate --lint
sam build --use-container
```

The container build uses a Lambda-compatible Python environment for packages
with native code. If Docker is unavailable, use Python 3.12 locally and run
`sam build` without `--use-container`.

### 3. Deploy the stack

Run:

```bash
sam deploy --guided
```

Use `readright-api` as the stack name and select `ap-southeast-1` for Singapore.
The stack creates a new private recording bucket in its own Region; it does not
reuse the existing empty Sydney bucket. The generated bucket name is included
in the `MediaBucketName` output. The existing bucket is left in place; media is
not copied between buckets. The bucket name is generated by CloudFormation; use
the output value when configuring the external analysis service role.
Allow SAM to create the function's IAM role (`CAPABILITY_IAM`). Enter these
parameters when prompted:

- `SupabaseUrl`
- `SupabaseServiceKey`
- `BackendApiKey`
- `MaiBaseUrl` — accept the default unless the MAI service owner gives you a
  different base URL
- `MaiApiKey` — obtain this from the MAI service owner; keep it private
- `AiAnalysisUrl` — base URL for the asynchronous reading analysis service
- `AllowedOrigin` — the frontend origin, such as `https://app.example.com`

Leave the version and size parameters at their documented defaults unless the
reading pipeline owner sets different values: `PipelineVersion`,
`ScoringPolicyVersion`, `AssignmentPolicyVersion`, `ProcessingTimeoutMinutes`
(10), and `MaxUploadBytes` (157286400). `SCORING_POLICY_VERSION` identifies
the code version for the 80/59/58 comprehension bands and is sent with each
analysis request.

If SAM warns that the API has no API Gateway authorizer, confirm the deployment:
authentication is handled by the FastAPI routes (`Bearer` token for the
dashboard and `X-Backend-Key` for trusted backend CRUD). When asked whether to
save the prompted values to `samconfig.toml`, choose **No** so the secret values
are not written to a local config file. At `SAM configuration file
[samconfig.toml]:`, press **Enter** to accept the filename; at the later save
prompt, answer **n**.

When deployment completes, copy `ApiUrl` and check the regular API:

```bash
curl https://YOUR_API_ID.execute-api.YOUR_REGION.amazonaws.com/health
```

The expected response is `{"status":"ok"}`.

Give the AI analysis service role the S3 permissions in
[`media-storage.md`](media-storage.md), using the deployed `MediaBucketName`.
The EventBridge schedule invokes a timeout sweep every minute; each sweep marks
processing sessions older than `ProcessingTimeoutMinutes` as failed only when
no completed or partial analysis exists.

The MAI submission route returns `202` through `ApiUrl`; poll the returned
`status_url` for the result. The worker's 150-second timeout covers the MAI
120-second SLA. SAM marks secret parameters as `NoEcho`. When SAM asks whether
to save prompted parameters to `samconfig.toml`, choose **No** so secrets are
not saved there.
